# Forging Quality Data & Rejection Analytics (QMS Project)

An end-to-end data quality pipeline for a **precision forged components** shop. It validates lot-level
inspection data, loads it into a star-schema warehouse, and produces the KPIs a Quality Management
System (QMS) team uses for RCA and CAPA: rejection %, first-pass yield, defect Pareto, die-life impact
and process capability (Cp/Cpk).

> **Note:** The dataset is **simulated** (generated by `src/generate_data.py`) so the project can be
> shared publicly. The data patterns are realistic but not from any real company.

## Architecture
```
Excel/CSV sources --> Python (Pandas) validation --> PostgreSQL / SQLite star schema --> SQL KPIs --> Power BI
                          |                                   ^
                          +--> quarantine CSVs                Airflow DAG (nightly)
```

## Tech stack
Python, Pandas, NumPy, SQL (PostgreSQL / SQLite), SQLAlchemy, Apache Airflow, Power BI (DAX, Power Query)

## Project structure
```
data/raw/          source files (generated)
data/processed/    quarantined bad records + data-quality summary
sql/schema.sql     star schema (1 lot fact + rejection fact + measurement fact, 6 dimensions)
sql/kpi_queries.sql  KPI and RCA queries
src/               generate_data.py | validate.py | etl.py | kpis.py | config.py
dags/              Airflow DAG (nightly 01:00)
powerbi/           data model, DAX measures, dashboard layout
reports/           KPI CSV exports for Power BI
```

## Quick start
```bash
pip install -r requirements.txt
python run_pipeline.py            # generate data -> validate/load -> KPI export
```
To use PostgreSQL instead of SQLite:
```bash
export DATABASE_URL=postgresql+psycopg2://user:password@localhost:5432/forging_qms
python run_pipeline.py
```

## Data validation rules
| Rule | Example |
|---|---|
| Duplicate lot_id | same lot loaded twice |
| Mandatory fields | missing machine_id, die_id |
| Quantity checks | negative qty, inspected > produced, rejected > inspected |
| Referential integrity | unknown part / die / machine |
| Range check | hardness outside 0-70 HRC |
| Measurement checks | missing dimension value |

Rejected rows go to `data/processed/quarantine_*.csv` with a `reject_reason`, and a
`dq_summary.csv` records the pass rate for every run (about 87% in the sample data).

## Key findings from the sample data (RCA)
1. **Die wear drives rejection.** Rejection climbs from about 1.5% (new die) to about 5.8% (die at 75%+ of its life).
   Recommendation: schedule die changes or re-sharpening before 75% of die life.
2. **Tooling defects dominate.** *Dimensional* and *Die Wear Mark* are about 55% of all rejections (Pareto).
3. **Night shift and machine FP-03** show higher rejection than the others, so check the process
   parameters and heating on FP-03.
4. **PF-101 is only marginally capable** (Cpk about 1.17 against a 1.33 target), so the process needs centering or variation reduction.
